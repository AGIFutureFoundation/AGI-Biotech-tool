# biodao.blockchain Hourly Review Report

## Timestamp

## Phase Status
- **Phase 0 (core WebXR/docking server, `server/server.py` lines 1-495)**: real, working stdlib HTTP server wired to RDKit/OpenMM/pypdf. Good quality.
- **Phase 1-3 (`server/server.py` line ~497 onward — auth, projects, reporting, agents, voice/orchestrator)**: **does not run at all.** No `Flask` is ever imported and no `app = Flask(...)` is ever created anywhere in `server/server.py`, yet every route from line 512 onward is decorated `@app.route(...)`. Importing this part of the module raises `NameError: name 'app' is not defined` on the very first decorator. Additional breakage once that's fixed: `process_voice_command` is defined twice as a Flask view (lines 743 and 1045 — Flask rejects duplicate endpoint names); `AgentOrchestrator()` is instantiated with zero args at line 870 but `AgentOrchestrator.__init__(self, master_agent, agent_team)` (agent_orchestrator.py:208) requires two; `MasterAgent(orchestrator=..., streaming_server=...)` is called but the base `MasterAgent` takes no constructor args (only its subclass `MasterAgentWithOrchestration` does); three separate `if __name__ == '__main__':` blocks each call a blocking `app.run()`/`serve_forever()`.
- **Phase 4 (hardening: `error_recovery.py`, `workflow_persistence.py`, `monitoring.py`)** and **Phase 5 (scaling: `load_testing.py`, `database_migration.py`, `performance_optimization.py`, `scaling_infrastructure.py`)**: internally coherent as libraries but never imported by `server/server.py` — dead code from the running app's perspective. See Enterprise Hardening section.
- **Phase 9 (molecular research pipeline, Pyrene discovery, compound evolution)**: `MolecularDockingEngine.dock()` and `MolecularDynamicsEngine.run_simulation()` (molecular_research_pipeline.py) fabricate binding energies/RMSD via `random.random()`/`random.gauss()` despite docstrings claiming AutoDock Vina/OpenMM integration. `team_agent_orchestration.py:244` calls `ADMETPredictor.predict_admet(smiles=..., mw=...)` with kwargs that don't match its actual signature `(compound_id, mol_weight, logp, hba, hbd)` — TypeError on every real invocation. `continuous_compound_evolution.py` defines `_calculate_composite_score` twice in the same class (lines 318 and 462); the second silently shadows the first. `pyrene_apoptotic_discovery.py:545`'s `batch_molecular_dynamics` is lookup-table arithmetic, not a simulation.
- **server/agents.py**: every "agent" method (`optimize_docking_params`, `identify_hotspots`, `predict_synthetic_accessibility`) ignores its real inputs and returns the same hardcoded result regardless of target/compound. `execute_bash_job` runs `subprocess.run(command, shell=True, ...)` with no sandboxing despite a docstring claiming one — arbitrary command execution if ever exposed.
- **server/websocket_streaming.py**: `StreamingServer.broadcast()` never sends anything over any socket (comment: "In production, use WebSocket send"); `register_client` takes one arg but is called with two from `server.py:981`; `subscribe_client`/`broadcast_to_clients` are called elsewhere but don't exist on the class.

**Bottom line: the "Phase 1+" Flask application in `server/server.py` cannot currently be imported, let alone run**, because of the missing `app` definition. That is the single highest-priority bug in the repo — more fundamental than the security issues below, since right now none of the auth/project/agent endpoints are reachable at all. It also means the auth bypass and privilege-escalation bugs fixed in this PR are not yet live in production, but they would become live the moment someone fixes the `NameError` (an obvious, likely-near-term fix) — which is exactly why fixing them now, ahead of that, is still the right call.

## Compliance Score
15/100 — the live auth system had two critical, unauthenticated-reachable vulnerabilities (now fixed in this PR); the module that would serve them cannot currently even start; and most of the "enterprise"/"Phase 4-9" features described in the docs are either unreachable dead code or randomly-generated fake results rather than real computation.

## Database Integration
FAIL — the Python "integration" modules (`biotech_database_integration.py`, `biotech_molecular_integration.py`) that claim 30+ live database connectors (ClinicalTrials.gov, STRING, Reactome, InterPro, Protein Atlas, UniChem, PDBe, gnomAD, etc.) contain zero real HTTP calls — methods literally comment "Simulate query execution" and return hardcoded fake records (CHEMBL1, CID-123, P12345...). The real, working integrations exist, but only client-side in `js/api.js`, plus a generic allowlisted proxy (`proxy_get`/`/api/proxy`) in `server/server.py` (the pre-line-497 working section) that those client calls fall back to on CORS failure.

## Enterprise Hardening
FAIL — `error_recovery.py`, `workflow_persistence.py`, `monitoring.py`, `load_testing.py`, `performance_optimization.py`, and `scaling_infrastructure.py` are never imported anywhere in `server/server.py`; no `/health` or `/metrics` endpoint exists. Specific gaps: the circuit breaker's `is_available()` is computed but never consulted before a retry attempt, so an "open" breaker never actually stops a call; `workflow_persistence.py` can save/load checkpoints but has no resume-from-checkpoint method, and nothing calls `get_latest_checkpoint` anyway; `load_testing.py`'s workload generator calls `asyncio.sleep()` instead of hitting any real endpoint; `scaling_infrastructure.py`'s `AutoScaler` only appends to an in-memory list and never scales anything real; SQLite connections in `workflow_persistence.py`/`database_migration.py` are opened without `with`/`finally`, leaking on exception paths.

## Top Issues (Priority Order)
1. **CRITICAL (blocking everything) — `server/server.py` Flask section cannot run at all**: no `Flask` import, no `app = Flask(...)`, so every `@app.route` from line 512 on raises `NameError` at import time. Not fixed in this PR — this is an architecturally significant rewrite (also needs: dedup the two `process_voice_command` views, fix `AgentOrchestrator()`/`MasterAgent()` constructor call mismatches, resolve three competing `__main__` blocks) and deserves its own dedicated PR with the author's input on which "Phase" code should actually be wired up, not a drive-by fix bundled into a security patch.

4. **HIGH — IDOR on project access**: `GET /api/projects/<id>` had no ownership/membership check. FIXED in this PR.
5. **MEDIUM — Hardcoded JWT signing secret**: defaulted to the literal string `'dev-secret-change-in-production'`. FIXED in this PR.
6. **HIGH — Database integrations are decorative** (see above). Not fixed — larger scope, not security-critical.
7. **HIGH — Molecular docking/MD/ADMET results are randomly fabricated, not computed**: `MolecularDockingEngine.dock()`, `MolecularDynamicsEngine.run_simulation()`, and the ADMET call-signature mismatch in `team_agent_orchestration.py`. This directly undermines the project's core scientific claims and should be prioritized above the dead hardening code.
8. **MEDIUM — Enterprise hardening modules are unreachable dead code** (see above). Not fixed — larger feature-level effort.
9. **LOW — No audit trail**: no action anywhere logs who did what and when.
10. **LOW — User IDs derived from `MD5(email)`**: not a security control, but allows offline enumeration/correlation of emails from user IDs.
